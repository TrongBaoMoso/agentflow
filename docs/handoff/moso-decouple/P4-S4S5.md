## What was built

### S4: document-esign (#138)

- **A new caller and service type.**
  - `ServiceType.RECRUIT` and caller `internal.callers.RECRUIT` → `[RECRUIT]`.
  - The folder tree is `Generated_Documents` + `Compliance`.
  - The bucket is optional (`DMS_RECRUIT_BUCKET`; blank means the shared storage).
  - `V52`: one RECRUIT root per offer.
  - The staging NetworkPolicy admits `recruit-be`.
- **Internal door only.** The internal e-sign door serves RECRUIT, because it is not app-delegated. The user door, the DMS public routes and the view link refuse it, like an app-delegated type.
- **Non-loan signer path.** On a RECRUIT envelope, every signature line belongs to the record's own person.
  - `ca_compliance_statement` marks its line `LOAN_OFFICER`. The 1099 and W-2 agreements leave theirs unannotated.
  - So the Loan Officer gets one participant and one link, and `SignerSlotPlanner` never calls tera-be.
  - A RECRUIT send with zero or two signers is refused: `400 ONE_SIGNER_REQUIRED`.
- **Per-signer `redirectUrl`.** Internal door only, absolute https. It tells Inkless where to return that signer. The default is unchanged.
- **Docs fix.** `ILO_AGREEMENT`, not `LO_AGREEMENT`. The completion event already publishes every source.

### S5: recruit-be (#906, D409)

- **Route.** `GET /public/api/v1/onboarding/signing-link`. It uses the same key, token header, rate limit and `no-store` as the other portal routes, and answers 404 while the flag is off.
- **Answer.** `{state, url_signing_sessions, lo_agreement_signed}`, where `state` is one of:
  - `READY`: the Inkless link is in `url_signing_sessions`.
  - `LOCKED`: the 1-1 is not done or the fee is not settled.
  - `PROCESSING`: just signed, being recorded.
  - `SIGNED`.
  - `NOT_AVAILABLE`: a MOSO-linked Loan Officer, an offer that is not SENT, or no e-mail.

  It answers 503 when document-esign cannot produce the link right now.
- **Who.** Only `legacy_key` blank. A MOSO-linked Loan Officer keeps packs' envelope.
- **When.** packs' `isSigningLinkServable`: the 1-1 is done AND the fee is PAID, WAIVED or switched off. The envelope is created on the first ask after that point.
- **Documents.** A port of packs' `computeRequiredDocs`, in `RequiredAgreementDocs`:
  - W-2 if corporate, else 1099.
  - Plus CA compliance if CA is sponsored and the DRE is not endorsed.
  - Plus exclusive agent if 1099 and licensed in VA or MS.
  - `ilo_1099_agreement` and `olo_w2_agreement` count as signed.
  - The documents already signed on this offer are subtracted.
- **Envelope.**
  - Inkless only: refused when document-esign reports no Inkless.
  - There is one live row per offer in `agreement_envelopes` (V343).
  - **Reused** while the documents and the printed values are unchanged.
  - **Superseded** (`supersedesEnvelopeId`) when they change.
  - **Re-sent** when document-esign reports it dead. A COMPLETED envelope is recorded, never superseded.
  - The idempotency key is built from the offer, the documents, the printed values and the envelope count.
  - Two concurrent requests are safe: `INSERT … ON CONFLICT DO NOTHING`, and the loser cancels its orphan.
- **Signed.**
  - Recruit listens to `ESIGN_ENVELOPE_COMPLETED_TOPIC` on its own subscription, keeping only `source=ILO_AGREEMENT` and `service_type=RECRUIT`. An envelope with no row yet is nacked for redelivery.
  - If the event is late, the envelope is read back as COMPLETED on the next ask.
  - Either path stores the signed file ids and, once every required agreement is signed, calls `OfferService#markSigned` under the offer lock. It is idempotent.

```
{ "serviceType":"RECRUIT", "parentId":"<offer id>", "source":"ILO_AGREEMENT",
  "envelopeName":"ILO Agreements - <full name>",
  "documents":[{"templateId":"<id from GET /templates?code=>","fillData":{...}}],
  "signers":[{"firstName","lastName","email","redirectUrl"?}],
  "useInklessSend":true, "idempotencyKey":"rcr1-<59 hex>", "supersedesEnvelopeId"?:"<old id>" }
GET  /internal/api/v1/esign/availability            (useInkless + inklessConfigured)
GET  /internal/api/v1/esign/templates?code=<code>   (id + declared inputs)

Topic ESIGN_ENVELOPE_COMPLETED_TOPIC (snake_case): envelope_id, service_type, parent_id, source, documents[].template_code/signed_file_id
```

## PDF comparison (Bao 08/11: we do it ourselves)

Tool: [`esign-compare/compare.py`](esign-compare/compare.py). It needs only stdlib and poppler (`pdftotext`, `pdftoppm`). Fixtures are in [`esign-compare/combos.json`](esign-compare/combos.json): 6 staging leads `bao.trinh+esign-c1…c6@loanfactory.com` with fictional names, one per document mix, and their expected documents. **Nothing touches DE until #138 is on DE staging:** `collect` and `cancel` refuse to run without `--i-know-de-has-138`.

**Why this costs (almost) nothing.** The PDFs compared are the **unsigned renders DE files for every envelope** (`sessions[].generatedFileId` in DMS `Generated_Documents`). These are the exact bytes the Loan Officer signs, produced through Recruit's real path: rule, fill data, DE send.
- Inkless bills only a COMPLETED envelope.
- So the 6 envelopes are created, collected and then **cancelled unsigned**: 0 billed.
- Only the one E2E envelope is signed (billed once).
- No second render path is involved: DE's `mode=PDF` preview needs a tera-be loan, so it cannot be used for RECRUIT, and is not.

**Steps (after #138 is on DE staging and `RECRUIT_FEATURES_ESIGN_DE=true` on staging):**
1. `python3 esign-compare/compare.py rule`. This checks recruit-be's rule against the 6 fixtures (offline). It prints OK for all 6 today.
2. **Leads.** For each combo, use the D399 flow on staging Recruit:
   - Add a lead with its `bao.trinh+esign-cN` e-mail (no MOSO record), claim it, and send the offer with `approve_now`.
   - Mark the 1-1 DONE (D411).
   - Fee: waive it at approve, or pay with the PayPal sandbox.
   - On the portal (`?invite=`), fill the fixture's answers: W-2/1099, licensed states, sponsor states, DRE, and the shared NMLS and address in `profile`.
   - Then open the sign step **once** (or call `GET …/signing-link`). That creates the envelope. Do **not** sign. Note the offer ids.
3. Collect the renders:
   ```
   kubectl --context gke_lenderrate-master_us-central1_moso-kube -n document-esign port-forward svc/document-esign 18092:8092
   python3 esign-compare/compare.py collect --i-know-de-has-138 --out <scratch>/cmp --offer c1-1099=<offerId> ... --offer c6-1099-ca-ea=<offerId>
   ```
   This writes `<scratch>/cmp/de/<combo>__<template>.pdf` and `manifest.json`.
4. Clean up: `python3 esign-compare/compare.py cancel --i-know-de-has-138 --out <scratch>/cmp`. It cancels only envelopes still SENT, never a signed one.
5. **MOSO references.** One PDF per template, put in `<scratch>/moso/<template_code>.pdf`. Never use a real Loan Officer's signed agreement (PII). In order of preference:
   - (a) MOSO staging, staff **Generate Doc** on a test loan, filled with the fixture values (packs `GenerateFormOp`: no Inkless, nothing sent).
   - (b) A signed staging agreement of an earlier MOSO test LO (bao.trinh+…), if one exists.
   - Never the packs ILO envelope path: packs warns that its staging Inkless is the billable production account.
6. `python3 esign-compare/compare.py compare --out <scratch>/cmp --moso <scratch>/moso`. This writes `<scratch>/cmp/compare.html`:
   - per document, a text similarity score and a changed-lines diff (`pdftotext -layout`, whitespace normalized);
   - pages side by side (`pdftoppm` at 60 dpi).

   Publish it as a private Artifact for Bao.
7. **Accepted differences, recorded in the page.**
   - The CEO signature bitmap: DE prints the rule blank, with the caption.
   - `fill_date`, `text_1`, `text_2`: blank on both sides.

   Anything else (wording, a missing page, address format) is a finding to fix in the DE template or in `AgreementFillData` before production.
8. **E2E.** Sign one envelope (the c6 lead covers 1099 + CA + exclusive agent). Expected: back on `?signed=1`, offer SIGNED, `agreement_envelopes` COMPLETED with `signed_files`.

The self-test ran 08/11 with two dummy PDFs: compare wrote the page, the text diff and the page images, and the guard refused `collect`.
